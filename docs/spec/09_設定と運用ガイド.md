# 09 設定と運用ガイド

## 1. 導入・初期設定チェックリスト

| 順 | 項目 | 確認・操作 | 参照 |
|---|---|---|---|
| 1 | 前提プラグイン | 社員管理（employee-manager）、拘束時間管理（`wp_kousoku_log`）、運行記録（`wp_tenrec_daily`）、打刻（MAT。**v3.2.0以上を推奨**）、有給管理（任意）が稼働していること | 01 §6.2 |
| 2 | 権限 | 利用者のロールに `access_custom_plugins` / `edit_custom_plugins` / `manage_custom_plugin_settings` が付与されていること（付与は本プラグイン外） | 01 §3.2 |
| 3 | プラグイン有効化 | 有効化で6テーブルを作成。以降、管理画面を開くたびに不足テーブル・列を自動補完（設定権限を持つ利用者の表示時） | 06 §2 |
| 4 | **種別管理** | 設定 > 種別管理で、**すべての職種**を「長距離」か「地場・事務」に設定（**未設定だと社員が画面に出ない**） | §3 |
| 5 | 休日マスタ | 所属ごとの所定休日ルールを登録 | §2 |
| 6 | 補正時間の適用開始月 | 初回表示時に**導入月が自動設定**される。過去月へ遡及したくなければそのまま。変更は §4 | §4 |
| 7 | 乗務員コード | 社員マスタに現行コードがあること。過去コードがある場合は社員管理で履歴を登録。設定画面の「未紐付けコード」で確認 | §5 |
| 8 | 動作確認 | 長距離・地場・事務それぞれ1名で月次表を開き、警告・数値を確認。集計一覧を読み込み | 03 |

> **重要**: 職種のマッピングが1つも無い場合、長距離は「拘束時間ログに現れるコードの一覧」にフォールバックしますが、この一覧は社員IDを持たず長距離画面・集計一覧は正常に動きません（12 ISS-03）。**必ず種別管理を設定してください。**

## 2. 休日マスタの運用

### 2.1 意味
所属×曜日×「その月の第n回目」を所定休日として登録します。所定休日は勤怠種別の自動判定（所定休／所定休出勤）に使われます（05 BR-14, BR-15, BR-18）。

### 2.2 登録例
| 所属 | 曜日 | 対象週 | 意味 |
|---|---|---|---|
| 本社 | 土曜日 | `2,4` | 毎月の第2・第4土曜日が所定休日 |
| 営業所 | 水曜日 | `1,3` | 第1・第3水曜日 |

### 2.3 運用上の注意
- 同一の（所属・曜日・対象週）の組み合わせは重複登録できません（UNIQUE制約。重複時はDBエラーメッセージが出る）。
- 対象週・曜日の**入力チェックはほぼありません**（数字以外を入れると、その週は一致しない＝休日にならないだけ）。`2,4` のように**半角数字とカンマ**で入力。
- 休日ルールを変更・削除・無効化すると、**過去月の表示も再計算で変わります**（勤怠種別の自動判定が毎回再計算されるため）。ただし**手動設定した日は変わりません**。過去月の確定結果を保存する機能（月次スナップショット）は**ありません**。
- 所定休は**月2日まで**自動で入ります（BR-15）。3日以上入る設定にしても、3日目以降は空欄になります。

## 3. 種別管理（職種→画面区分）

### 3.1 仕組み
- 職種の一覧は社員管理の `emp_get_job_types()` から取得。ラジオを選ぶと即時保存（`am_job_type_mapping`）。
- 画面に出る社員 = 「その区分に設定された職種」かつ「在籍（`is_active=1`）」。長距離は加えて乗務員コードが登録済みの社員のみ。
- 集計CSVでは、**職種が「長距離」または「郵便」**の社員の総労働時間に点呼10分/出勤日が加算される仕様がある（職種名の文字列一致。08 §2.2）。職種名を変更する場合は注意。

### 3.2 運用上の注意
- 区分を変更すると、社員は即座に別の画面に移動します。過去に保存した編集データ（`am_chokyo_*` / `am_jiba_*`）は**移動しません**（長距離画面で保存した分は長距離側の表に、地場側で保存した分は地場側の表に残る）。
- 設定を「未設定」へ戻す操作は無く、**解除するにはDBを直接操作**する必要がある（`am_job_type_mapping` の行削除）。【確定】
- 同じ職種を両方の区分に設定することはできない（職種名がユニーク）。

## 4. 補正時間（点呼など）の運用

- **適用開始月**: この月以降のみ補正時間が有効。それより前は0扱いで入力不可。初回は導入月が自動設定。
- 変更の影響: 開始月を**過去へ変更すると、その月以降の週計・月計・確定残業が変わる**（保存済みの補正時間は各日の行に残っているため）。**未来へ変更すると、それまでの月の補正が無効（0扱い）**になる。
- 既定は10分/日（始業終業のある日）。長距離は全日対象、地場・事務は「長距離フラグON」の日のみ。
- 集計CSVの点呼加算（長距離・郵便の出勤日×10分）との関係は 12 ISS-04 を参照。

## 5. 乗務員コード履歴・データ移行の運用

背景は `docs/crew-code-history-requirements.md`。実装状況は 05 §10。

### 5.1 通常運用（コードを変更するとき）
1. **社員管理プラグイン側**で、旧コードの終了日・新コードの開始日を登録（履歴テーブル `emp_crew_code_history`）。社員マスタの現行コードも更新される前提。
2. 勤怠管理の長距離画面で、対象月の「対象月の使用コード」に旧・新が並ぶこと、月次表が1人分として連続していることを確認。

### 5.2 未紐付けコードの対応
- 設定画面の「未紐付け乗組員コード」に出たコードは、**拘束時間ログに存在するが、社員にも履歴にも結び付いていない**。放置するとそのコードのデータは**どの社員の月次表にも出ない**。
- 対応: 社員管理で該当社員の編集画面から「過去コードを追加」（必要なら使用期間も設定）。

### 5.3 移行状況の数値の見方

| 項目 | 意味 | 目標 |
|---|---|---|
| 未移行 勤怠編集行 | `am_chokyo_kintai_log` で `employee_id` が NULL の行数 | 0（旧行は旧コードでの互換読込で動くが、解消が望ましい） |
| 未移行 繰越行 | `am_chokyo_carryover` で `employee_id` が NULL の行数 | 0 |
| 勤怠編集の衝突 | 同じ社員ID・同じ日の行が複数 | **0**（>0 は保存がエラーで止まる） |
| 繰越の衝突 | 同じ社員ID・同じ月の行が複数 | **0**（>0 は繰越が適用されない：警告E3） |

- 自動補完は管理画面表示時に実行され、「一意に特定できる行のみ」補完します。曖昧な行は残ります（手動対応が必要）。

### 5.4 同日にデータが重複する場合
同一社員の複数コードに同じ日の拘束時間データがあると、**エラー警告（E1）**を出して**先に読んだ行（コード昇順）だけを採用**します。元データ（CSV取込分など）を確認し、不要な行を削除するか、コードの有効期間を修正してください。

## 6. 拘束時間CSV取込の運用

- 取込は `wp_kousoku_log` を**直接変更**します。上書きモードを使う前に**必ずDBバックアップ**。
- 推奨手順: ①ひな形取得 → ②標準モード（スキップ）で取込 → ③結果の「既存スキップ」件数を確認 → ④本当に修正が必要な場合のみ上書きモード。
- エラーで全体が取り消されたときは、メッセージの行番号を修正して再実行（部分反映は起きない）。
- 取込後は、影響する社員の月（と翌月）を開き直し、**翌月繰越を更新**する。

## 7. 月次運用の推奨手順

| タイミング | 作業 |
|---|---|
| 月初（前月分の確認） | ① 前月分の元データ不足を CSV取込 などで解消 ② **前月の集計一覧を「読み込む」**（全社員の翌月繰越が最新になる） ③ 前月の各社員表で警告を確認・補正・保存 |
| 月次締め | 集計一覧を確認 → CSV出力 → 給与計算へ渡す |
| 随時 | 休日ルール・職種の変更（影響は過去月の再計算に及ぶことに注意） |

## 8. バックアップ・復旧の観点

- バックアップ対象: 本プラグイン所有6テーブル、`wp_kousoku_log`（CSV取込で変更されるため）、オプション `am_hosei_start_month`。
- 「保存した編集」は `am_*_kintai_log`、「月またぎの確定残業の元」は `am_*_carryover`。**計算結果そのものは保存されていない**ため、元データ（運行記録・打刻・拘束時間ログ）と休日ルール・補正開始月が同じなら、いつでも同じ結果が再現できる（外部データが変われば結果も変わる）。
- 締め後の数字を固定したい場合は、集計CSVを保管する（月次スナップショット機能は無い）。

## 9. トラブル対応（管理者向け）

| 症状 | 想定原因 | 確認・対処 |
|---|---|---|
| 社員が一覧に出ない | 職種が未設定／非在籍／長距離で乗務員コード未登録 | 種別管理、社員マスタ |
| 長距離の時間が全部空 | 乗務員コード履歴・社員マスタのコードが拘束時間ログと一致しない、有効期間外 | 「対象月の使用コード」と `kousoku_log.crew_code` を照合。未紐付けコード一覧を確認 |
| 同じ日に警告E1 | 複数コードの重複データ | §5.4 |
| 保存で「保存済み勤怠が複数コードに存在…」 | 旧コード行と社員ID行が同日に存在（移行の衝突） | 設定画面の「勤怠編集の衝突」件数。DBで重複行を整理 |
| 翌月の繰越行が出ない／古い | 前月が再計算されていない、繰越の衝突、`days=0` | 前月を開き直す、衝突件数を確認 |
| 有給残が「―」 | 有給管理テーブルが無い、社員コードが空 | 有給管理プラグインの有効化、社員コード |
| 打刻（MAT）側の時間が古い形式 | MAT が v3.2.0 未満で旧ロジックにフォールバック | MAT を更新（丸め済み始業終業・深夜を使うため） |
| 集計CSVの長距離社員の数字がおかしい | ISS-02（社員識別子の不整合） | 12 参照。画面（集計一覧）の数字と突き合わせる |
