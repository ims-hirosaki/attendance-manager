## ISS-01 長距離画面：連続保存で手動フラグが落ちる（重要度 中）

- **内容**: 保存成功後の画面更新（`refreshDailyRows`）が、勤怠種別セレクトを更新するたびに全行の `data-auto` を `'true'` に書き換える。保存処理は `data-auto === 'false'` の行だけを `is_manual = 1` として送るため、**ページを再読み込みせずに2回目の保存をすると、1回目で手動にした行が `is_manual = 0` で上書き**される。
- **根拠**: `assets/js/admin.js` `refreshDailyRows`（`$tr.attr('data-auto', 'true')`）と、長距離の保存ハンドラ（`is_manual: $tr.attr('data-auto') === 'false' ? 1 : 0`）。長距離の日次API（`chokyo_get_daily_rows`）は `kintai_type` を返す。
- **地場・事務は対象外**: 地場の日次APIは `kintai_type` を返さないため、`data-auto` は書き換わらない。
- **影響**: 次回表示時、その日の勤怠種別は自動判定に戻る（保存されている `kintai_type` 自体は残るが `is_manual=0` のため無視される）。例えば「欠勤」を手動で設定した日が空欄／出勤などに戻る。
- **暫定回避**: 保存したら**ページを再読み込み**してから次の編集をする。
- **修正案**: `refreshDailyRows` で `data-auto` を更新しない（または API が `is_manual` を返し、それを反映する）。

## ISS-02 集計CSV：長距離社員の識別子の不整合（重要度 高）

- **内容**: `AM_Summary_CSV_Exporter::write_category` は、長距離社員について `crew_code`（乗務員コード）を `$code` として取り出し、`AM_Compute_Chokyo::get_monthly_rows( $code, … )` / `get_weekly_summary( $code, … )` / `get_monthly_summary( …, $code, … )` に渡す。しかし 2026-08-26 の「乗務員コードの複数保有対応」以降、`AM_Compute_Chokyo` の第1引数は **`employee_id`（社員ID）**。集計一覧（`AM_Ajax::summary_list_get`）は正しく `employee_id` を渡している。
- **根拠**: `includes/class-am-summary-csv-exporter.php`（`$code = … $employee['crew_code']` → `$compute::get_monthly_rows( $code, … )`）／`includes/class-am-compute-chokyo.php`（`get_monthly_rows( $employee_id, … )`）／`class-am-ajax.php` `summary_list_get`。
- **影響（論理的に想定されるもの）**:
  1. 乗務員コード（例 `100`）が社員IDとして解釈され、**別の社員のデータで計算される、または空になる**。CSV の長距離行が画面（集計一覧）と一致しない。
  2. 週集計は、月をまたぐ週があると `save_chokyo_carryover( $key, … )` を呼ぶ。`$key` に乗務員コード数値が入るため、**同じ番号の社員ID を持つ別社員の翌月繰越データを書き込む／上書きする**可能性がある（データ汚染）。
  3. 長距離社員の有給サマリ（社員ID基準）も別人の値になり得る。
- **未検証**: 実環境で、乗務員コードと社員IDが衝突する具体例の確認は未実施。
- **地場・事務は対象外**: 社員コード（`employee_code`）を渡しており整合している。
- **暫定回避**: 集計CSVの長距離行は、集計一覧の画面と突き合わせて使う。CSV出力により繰越データが変更された可能性がある場合は、該当月（と翌月）を開き直して確認する。
- **修正案**: 長距離は `$employee['employee_id']` を使う（`get_employees_by_category('chokyo')` の返り値に `employee_id` がある）。`employee_id` が無い場合はスキップする（`summary_list_get` と同じ扱い）。

## ISS-03 種別管理が未設定だと長距離が動かない（重要度 中）

- **内容**: 職種マッピングが1件も無いと、長距離の社員一覧は拘束時間ログ起点（`get_employees_from_kousoku`）にフォールバックするが、この一覧は `employee_id` を含まない。
- **影響**: 長距離画面の社員セレクトの `value` が空（未定義インデックスの警告）になり選択できない。集計一覧は `employee_id` が無い社員をスキップするため長距離が出ない。
- **根拠**: `AM_DB::get_employees_by_category`、`get_employees_from_kousoku`、`templates/chokyo-page.php`（`$emp['employee_id']`）、`AM_Ajax::summary_list_get`（`if ( ! $employee_id ) continue;`）。
- **対処**: 運用上は**職種の種別管理を必ず設定**する（09 §1）。修正するならフォールバック時に `emp_master` から `employee_id` を引く。

## ISS-04 集計CSVの点呼10分加算と補正時間の二重算入（重要度 中・要確認）

- **内容**: 集計CSVは「総労働時間（点呼時間含む）」で、職種が「長距離」「郵便」の社員に**出勤日数×10分**を加算する（2026-09-16）。一方、補正時間機能（2026-09-29）で、週集計の労働時間にはすでに**補正時間（既定10分/日）**が含まれる。
- **影響**: 補正時間の適用開始月以降は、長距離の労働時間に点呼が**二重に加算**される可能性（出勤日×20分）。「郵便」は地場・事務区分のため補正は長距離フラグONの日のみ。CSVは全出勤日に加算するため、不一致が起き得る。
- **確認したいこと**: CSVの加算は補正時間導入に伴い廃止予定か、どちらが正か。
- **根拠**: `class-am-summary-csv-exporter.php`（`in_array( $job_type, [ '長距離', '郵便' ] )` で `+10*出勤日数`）と `_build_weekly_static`（`labor_min += hosei_min`）。

## ISS-05 月またぐ週：日残業が確定残業に入らないケース（重要度 中・要確認）

- **内容**: 月末をまたぐ週は、前月では確定残業を計上せず（BR-22）、翌月の第1週の確定残業は `max(翌月側の日残業合計, 繰越込みの週残業)` で、**繰越側（前月分）の日残業は加算されない**。そのため「前月側で日残業はあるが、週の合計は40時間以内」の場合、その日残業はどちらの月の確定残業にも入らない。
- **実行検証**（PHP で再現）: 2026年9月28日(月)に労働11:00のみ（日残業3:00）、10月1日(木)に労働8:00。→ 9月の日残業合計 3:00・確定残業 0:00、10月の第1週（前月繰越行）日残業 3:00 を表示するが、第1週の確定残業 0:00、10月の確定残業合計 0:00。**3:00の日残業が確定していない**。
- **確認したいこと**: 「確定残業=日残業と週残業の大きい方」の会社ルールを、月またぎ週にどう適用する意図か。繰越の日残業を翌月第1週の「日残業」に加算すべきか。
- **根拠**: `_build_weekly_static`（繰越時 `$sum['overtime_min']` に `$carry_overtime` を加算しない、繰越週は `confirmed_overtime = null`、合計で繰越週を除外）。

## ISS-06 保存・設定まわりの検証不足（重要度 低〜中）

| # | 内容 | 影響 |

| a | 地場・事務の保存はトランザクション無し（長距離はあり） | DBエラーが途中で起きると、先頭の行だけ保存済みの状態になる |
| b | 休日ルールの `day_of_week`・`week_numbers` の書式・範囲を検証しない | 不正値は「休日にならない」だけだが、気付きにくい |

## ISS-07 JS の属性値の未エスケープ（重要度 低）
- `assets/js/admin.js` `hmReloadTable` が、`week_numbers` などを `data-*` 属性へ未エスケープで連結している。種別管理の行も `data-name` を引用符エスケープなしで組み立てている。
- 入力できるのは `manage_custom_plugin_settings` 権限者のみで、PHP 側は `sanitize_text_field` を通すが、属性内の引用符は除去されない。権限者による自己XSS程度の低リスクだが、`esc_attr` 相当の処理が望ましい。

## ISS-08 リポジトリ内の実データ・ドキュメントの扱い（重要度 低〜中・要確認）
- `拘束時間管理表_2026-07-01_upsert.sql`（実際の拘束時間データ 1,714 行、乗務員コード・日付・摘要等を含む）が、Git リポジトリ直下にコミットされている。
- デプロイは `local-dir: ./`（リポジトリ全体）の FTP 転送で、除外設定が無い（staging / personal は `./`、production は未指定で既定）。そのため `docs/`、`.codex-build/`、上記SQL もサーバーのプラグインディレクトリに置かれ得る。
- **確認したいこと**: デプロイ先が Web から直接参照可能か、実データを Git に残してよいか、`.gitignore` / デプロイ除外の整備。

- `docs/crew-code-history-requirements.md`: ステータスが「要件定義（実装前）」のまま。実装は進行済み（05 §10）。
- 利用者向けガイド（docx 2026年8月版）: 補正時間、振替なし法定休出勤、拘束CSV取込、集計CSVなどは未記載。

## ISS-10 性能・設計上の特徴（重要度 低）
- 画面表示（GET）や集計一覧・CSV出力・保存後の再取得が、**翌月繰越の DB 書き込み**を伴う（BR-22）。読み取りだけのつもりの操作で書き込みが走る。
- `migrate_existing_tables` が、設定権限者の**管理画面表示のたびに**複数の `SHOW …` と `UPDATE … JOIN` を実行する。
- 集計一覧・集計CSVは全社員を1リクエストで計算する（社員数に比例）。
- `tenrec_daily` は月の全日の JSON を取得して PHP 側で氏名検索する。

## ISS-11 データ仕様上の癖（重要度 低）
- 運行記録（tenrec）の社員照合は**氏名の完全一致**（前後空白除去のみ）。表記ゆれ・同姓同名で取りこぼし／誤採用が起き得る。
- 長距離の労働時間は「運転時間が無ければ 0」（積卸のみのデータでも 0）。tenrec のみで拘束時間ログが無い日は、労働・運転・積卸・日残業が空欄（合計では 0）。
- 長距離の「休憩時間」は拘束−労働の**差し引き**で、拘束時間ログの `break_min` は使わない。
- MAT公開API無し（v3.2.0未満）の旧パスでは、深夜時間を再計算しない。
- 日またぎ判定は「終業 ≦ 始業」でも日またぎとみなす（始業・終業が同時刻の場合は24時間）。

## ISS-12 編集権限が無くても保存ボタンが見える（重要度 低）
- 画面は `access_custom_plugins` で表示され、保存ボタンも常に表示される。`edit_custom_plugins` が無い利用者が押すと AJAX が拒否される（`wp_die(-1)`）が、画面のメッセージは「通信エラー」等になり原因が分かりにくい。ボタンの出し分け、または明確なメッセージが望ましい。
