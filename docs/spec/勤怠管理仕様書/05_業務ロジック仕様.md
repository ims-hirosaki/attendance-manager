# 05 業務ロジック仕様

> この文書は本システムの**中核**です。「なぜこの数字になるのか」を説明します。
> 各ルールに `BR-nn` を付けています。確度ラベル: **【確定】**=コードから事実、**【推定】**=意図の推測、**【要確認】**=担当者確認が必要。
> 時間は内部では「分」。画面では `H:MM`。以下、断りがなければ両方の表記を併記します。

## 0. 全体パイプライン

画面表示・再計算のたびに、次の順で月次表を組み立てます（長距離: `AM_Compute_Chokyo::get_monthly_rows`、地場・事務: `AM_Compute_Jiba::get_monthly_rows`）。

```
[入力]  社員 × 対象月（YYYY-MM）
  │
  ├─ 0. 準備：乗務員コード解決(BR-02)・元データ取得・保存済み編集・休日ルール・有給消化日・繰越を取得
  │
  ├─ パス1：月の全日付(1日〜末日)の行を作り、元データから時間を自動算出(BR-03〜05, BR-07)
  │         ＋勤怠種別の初期判定(BR-10)
  │
  ├─ パス2：保存済み編集を適用(BR-11)
  │         ＋「地場/長距離フラグ」ON日は別の元データへ切替(BR-06, BR-08)
  │
  ├─ 補正時間の適用(BR-09)
  ├─ 有給消化日の反映(BR-12)
  ├─ 勤怠種別の自動補正(BR-13)
  ├─ 自動割当：所定休の上限(BR-15)・法定振替休(BR-16)・警告(BR-27)
  │
  ├─ パス3：法定休出勤/所定休出勤フラグ(BR-18)、振替なし法定休出勤の判定(BR-19)、件数不一致警告
  │
  └─ [出力] 日次行の配列（先頭行に警告 _alerts を持たせる）

  → 週集計 get_weekly_summary(BR-20〜22) … ここで翌月繰越の保存も行う
  → 月間サマリ get_monthly_summary(BR-23〜25)
```

## 1. 対象社員の決定

### BR-01 画面に出る社員（種別管理）【確定】
`AM_DB::get_employees_by_category( 'chokyo' | 'jiba' )`

1. 種別管理（`am_job_type_mapping`）で、その区分に設定された職種名の一覧を取得。
2. **設定がある場合**: `emp_master` のうち、職種名が一致し、`is_active = 1` の社員を、社員コード数値順に表示。
   - 長距離は追加で `crew_code` が空でない社員のみ。
3. **設定が一件も無い場合（フォールバック）**:
   - 長距離 → 拘束時間ログに登場する乗務員コードから一覧化（`get_employees_from_kousoku`）。
   - 地場・事務 → 打刻データに登場する社員コードから一覧化（`get_employees_from_mat`）。
4. 注意: フォールバックの長距離一覧は `employee_id` を持たないため、長距離画面・集計一覧では正しく動作しません（ISS-03 参照）。**実質、種別管理の設定が必須**です。【要確認】

### BR-02 乗務員コードの解決（長距離・地場の長距離フラグ日）【確定】
`AM_DB::get_crew_codes_for_period( employee_id, 月初, 月末 )`

- 社員管理プラグインの関数 `emp_get_crew_codes_for_period()` があればそれを使う。
- 無ければ `wp_emp_crew_code_history` を直接参照し、対象期間と重なる（`valid_from <= 月末` かつ `valid_to >= 月初`、NULL は無制限）行を取得。
- 履歴が空なら `emp_master.crew_code`（現行コード）を1件の履歴（期間無制限）として扱う。
- 拘束時間ログの各行は、**そのコードが勤務日（work_date）に有効な履歴行に当てはまる場合のみ採用**（`crew_code_applies_on`）。
- 結果、月の途中でコードが変わっても、1人分の1か月として統合される。

## 2. 日次の時間の算出

### BR-03 長距離：元データの優先順位【確定】
長距離の1日分は、**運行記録（tenrec）** と **拘束時間ログ（kousoku）** を合わせて作ります。

| 項目 | 取得元 |
|---|---|
| 始業時刻 | tenrec の `g1_time`（空でなければ）→ なければ kousoku の `start_time`（HH:MM） |
| 終業時刻 | tenrec の `g7_time` → `g5_time` → `g3_time` のうち最後に値がある方 → なければ kousoku の `end_time` |
| 運転時間 | kousoku の `drive_min` |
| 積卸時間 | kousoku の `cargo_min` |
| 深夜・残業 | kousoku の `midnight_min` / `overtime_min` / `overtime_midnight_min` |

- tenrec は日付ごとの `entries`（JSON配列）の中から、`driver` が**社員名と完全一致**（前後空白除去）する最初の1件を採用します。【確定】（同姓同名・表記ゆれがあると取れません）
- **データあり（has_data）** = kousoku の行がある、または tenrec の行がある、のいずれか。
- tenrec のみで kousoku が無い日: 始業・終業・拘束時間は出るが、労働・運転・積卸・休憩・深夜・日残業は空欄（週・月合計では 0 扱い）。

### BR-04 拘束時間と日またぎ【確定】
- 始業・終業が両方あるとき: `拘束時間 = 終業 − 始業`（分）。
- **日またぎ判定**: kousoku の `end_next_day` が 1、または 終業 ≦ 始業 のとき、終業を `(時+24):分` 形式で表示し、24時間(1,440分)を足して計算する（例 終業 10:19 → 表示 `34:19`）。

### BR-05 労働・休憩・深夜・日残業（長距離）【確定】
kousoku の行があるとき:

| 項目 | 計算 |
|---|---|
| 労働時間 | 運転・積卸ともにあれば `運転 + 積卸`／運転のみなら運転／**運転が無ければ 0** |
| 休憩時間（画面表示） | `max(0, 拘束時間 − 労働時間)`（実績の休憩ではなく**差し引き**） |
| 深夜時間 | `midnight_min + overtime_midnight_min`（どちらか一方でもあれば合算。両方 NULL なら空欄） |
| 日残業 | `overtime_min + overtime_midnight_min`（どちらか一方でもあれば合算）。**両方 NULL のときだけ** `max(0, 労働時間 − 480分)` |

- 「時間外深夜は深夜・残業の双方へ算入する」のは**会社の手当計算ルール**とコードコメントに明記されています。【確定】
- 拘束時間ログの他の列（重複運転、休息、累計、前後運転平均など）は本プラグインの計算では使いません。

### BR-06 長距離画面の「地場」スイッチ ON の日【確定】
その日は打刻（MAT）から時間を取得して、BR-03〜05 の結果を**上書き**します（MAT にその日の記録がある場合のみ。記録が無ければ長距離側の値のまま）。

- MAT公開API版（`mat_get_daily_by_month()` があり、`kousoku_minutes` が返る）:
  始業 = 丸め後始業（空なら実打刻）、終業 = 丸め後終業（空なら実打刻）、拘束 = `kousoku_minutes`、労働 = `labor_minutes`、休憩 = `break_minutes`、日残業 = `overtime_minutes`、深夜 = `midnight_minutes`。
- 旧実装（API無し）: `拘束 = 終業−始業`（日またぎは+24h）、`労働 = 拘束 − 休憩分`、`日残業 = max(0, 労働−480)`。深夜は再計算しない。
- 運転・積卸は空欄（null）。has_data は true にする。

### BR-07 地場・事務：日次の時間【確定】
打刻（MAT）から取得（`AM_Compute_Jiba`）。

- MAT公開API版: BR-06 と同じ項目の対応。日またぎは MAT 側が `25:00` 形式で保持するため推測しない。
- 旧実装（API無し）: BR-06 の旧実装と同じ。
- **has_data** = 打刻の `clock_in` または `clock_out` のどちらかが空でない。
- 長距離フラグ初期値 = MAT 側の `long_distance` が真。
- 運転・積卸は常に空欄（null）。

### BR-08 地場・事務画面の「長距離」スイッチ ON の日【確定】
その日は運行記録（BR-03 と同じ優先順位）で上書き。

- 終業時刻は kousoku の `end_next_day` が 1 なら一旦 `(翌)` を付けて取得し、計算時に `(時+24):分` 形式へ正規化する。
- 労働 = BR-05 の労働時間（運転+積卸）、休憩 = `max(0, 拘束−労働)`、深夜・日残業は BR-05 と同じ。
- **拘束時間ログが無い日**: 始業・終業のみ表示され、労働・運転・積卸・休憩・深夜・日残業は空欄になる（has_data は MAT 由来のまま）。
- 長距離フラグは「**MAT のフラグ または 保存済みの手動フラグ**」のどちらかが ON なら ON（読み込み時に必ず自動反映）。
- 使用する乗務員コードは BR-02（社員コード→社員ID→履歴）で解決。

### BR-09 補正時間（点呼など）【確定】
`AM_Compute_Chokyo::apply_hosei( rows, 年月, フラグ列 )`

**有効条件（has_time）**: 次を**すべて**満たす日のみ。
1. 始業・終業が両方ある
2. 対象月 ≧ 補正時間の適用開始月（オプション `am_hosei_start_month`。未設定なら初回の管理画面表示時に「導入月」が自動設定される）
3. 地場・事務の場合のみ: その日の**長距離フラグが ON**（長距離画面ではフラグ不要）

有効な日は `補正時間 = 保存値（既定 10 分、負数は0）`、無効な日は `0`（入力不可）。

**日残業への反映**: 補正があり労働時間が分かる日は、
`日残業 += max(0, 労働+補正−480) − max(0, 労働−480)`
（＝「労働時間＋補正時間−8時間」となるよう、補正で新たに生じた超過分だけを加算。元の日残業に含まれる時間外深夜は保持）

**週・月への反映**: 週集計で `労働時間 += 補正`、`拘束時間 += 補正`、週残業判定にも `+補正`（BR-20, BR-21）。

> **重要（画面の見え方）**: 日次表の「労働時間」「拘束時間」列には補正は**含まれません**。**含まれるのは「日残業」（超過分）と、週計・月間サマリの労働時間・拘束時間**です。

検証済みの例（補正10分）:

| その日の労働時間 | 日残業への加算 |
|---|---|
| 7:50（470分） | +0 |
| 7:55（475分） | +5 |
| 8:00（480分） | +10 |
| 8:20（500分） | +10 |
| 10:00（600分） | +10 |

（元の日残業が「労働時間−8時間」の場合、補正後の日残業は上から順に 0:00 / 0:05 / 0:10 / 0:30 / 2:10 になります。）

## 3. 勤怠種別の決定

### BR-10 初期判定（自動）【確定】
各日の既定の勤怠種別:

```
データあり           → 出勤
データなし ∧ 日曜     → 法定休
データなし ∧ 所定休日 → 所定休   （BR-14）
それ以外             → （空欄「―」）
```

### BR-11 保存済み編集の適用（手動優先）【確定】
保存済み行がある日は次を**常に**適用: `is_manual`、地場/長距離フラグ、早退遅刻（`hayatai_min`）、備考、補正時間。
**`is_manual = 1` の行だけ**、勤怠種別（`kintai_type`）と振替ラベル（`furikae_label`）も保存値を採用する（＝自動判定を上書き）。
`is_manual = 0` の行は、保存されている勤怠種別を**無視**して自動判定を使う。

- 地場・事務では `hosei_min` が NULL の保存行は補正値を上書きしない（既定を使う）。

### BR-12 承認済み有給の反映【確定】
有給管理プラグインの消化日（`consumed_days` の合計が 0 超の日）に該当し、かつ**手動でない行**は、勤怠種別を「有給」にし振替ラベルを空にする。
（有給管理テーブルが無い環境では何もしない）

### BR-13 勤怠種別の自動補正（手動行はスキップ）【確定】
1. 「出勤」なのにデータなし → 日曜は「法定休」、所定休日は「所定休」、他は空欄に戻す。
2. 勤怠種別が入っていて、データがあるのに「法定休」「所定休」 → 「出勤」に直す。（有給・欠勤などはそのまま）
3. 勤怠種別が空欄 → データあり=出勤／日曜=法定休／所定休日=所定休。

### BR-14 所定休日の判定（休日ルール）【確定】
所属（`affiliation_id`）の**有効**なルール（`is_active = 1`）に対し、
「その日の曜日が `day_of_week` と一致」かつ「その曜日の**月内で何回目か**が `week_numbers`（カンマ区切り）に含まれる」なら所定休日。

- 「第n週」は**カレンダー週ではなく、月内のその曜日の n 回目**（1日からその日までに同じ曜日が何回あったか）。
- 検証例: 土曜・第2,4週 のルール → 2026-09-12（2回目）、2026-09-26（4回目）は所定休日、09-05 と 09-19 は対象外。
- ルールは所属単位。社員の所属が変われば休日も変わる。

### BR-15 所定休の月間上限【確定】
手動でない行について、月内で「所定休」と判定された日を日付順に数え、**3日目以降は空欄に戻す**（所定休日フラグ自体は保持）。手動で「所定休」にした日は数えず、そのまま。
その後、所定休（手動含む）が 2 日を超えていれば警告 W1。

### BR-16 法定振替休の自動割当【確定】
手動でない「日曜かつデータありかつ出勤」の日それぞれについて、**その日より後（同じ月内）で最初の候補日**を「法定振替休」にし、ラベルを `MM/DD(日)の振替` とする。

- **候補日の条件**: 勤怠種別が空欄 ∧ データなし ∧ 日曜でない ∧ 所定休日でない ∧ 手動でない。
- 候補日が無い場合は **エラー警告 E4**「MM/DD(日)の振替休を割り当てられる日がありません」。
- **月をまたいだ振替は行わない**（月末の日曜出勤で月内に候補日が無いとエラー）。
- 法定休（法定休＋法定振替休）の合計が **4〜5日の範囲外**なら警告 W2。

### BR-17 所定振替休の自動割当（現在は無効）【確定】
所定休日出勤に対する「所定振替休」の自動割当は、**既定で無効**（振替が任意になったため、2026-10-02 のコミット）。
定数 `AM_AUTO_SHITEI_FURIKAE_ENABLED` を `true` にすると再開（wp-config.php 等で定義）。
無効のままでも、**所定休出勤の回数と所定振替休（手動選択）の日数が一致しない場合の警告 W4 は出る**。

## 4. 休日出勤の判定

### BR-18 法定休出勤・所定休出勤フラグ【確定】
勤怠種別が「出勤」かつデータありの日について:
- 日曜 → **法定休出勤**（バッジ「法定休出勤」）
- 日曜でなく所定休日 → **所定休出勤**（バッジ「所定休出勤」）

（「緊急出動」の日はフラグが付かない。）
月間サマリの「休日出勤日数」= 法定休出勤 + 所定休出勤 の日数。

### BR-19 振替なし法定休出勤【確定】
`mark_unmatched_houtei_work`

1. 月内の「法定振替休」の日数 N を数える（自動割当・手動選択のどちらも）。
2. 法定休出勤の日を**日付の古い順**に、N 件まで「振替済み」とし、**残りを「振替なし法定休出勤」**とする。
3. 「振替なし法定休出勤」の日は:
   - 日次表・勤務時間の表示には残す。
   - **週の残業計算（日残業の合計・週40時間判定）から除外**する。
   - 月間サマリで「振替なし法定休出勤: 日数 / 実労働時間」として別集計（労働時間は補正を含まない）。
   - 集計CSVの「法定休日出勤日数」「法定休日労働時間」の元になる（08）。

【推定】意図: 振替休を取った法定休日出勤は通常の勤務日として残業計算に含め、振替休が無い法定休日出勤は法定休日割増の対象として残業から切り離す。（給与ルールの確認が必要）

## 5. 週集計と繰越

### BR-20 週の定義と集計項目【確定】
`AM_Compute_Chokyo::_build_weekly_static`（長距離・地場・事務で共通）

- 週は**日曜始まり〜土曜**。月初の週は、1日を含む日曜から始まる週（当月分のみ集計）。
- 各週について、当月内の日を数えて次を合計する（データありの日のみ）:

| 列 | 計算 |
|---|---|
| 日数 | 当月に属するカレンダー日数（勤務日数ではない） |
| 拘束時間 | Σ（拘束 + 補正） |
| 労働時間 | Σ（労働 + 補正） |
| 運転・積卸・深夜 | Σ |
| 休憩時間 | 拘束 − 労働（週合計の差し引き） |
| 日残業 | Σ 日残業（振替なし法定休出勤を除く） |
| 判定用労働時間 | Σ（労働 + 補正）（振替なし法定休出勤を除く） |

### BR-21 週残業・確定残業【確定】
```
週残業   = max(0, 判定用労働時間 − 2400分)        … 週40時間超の分
確定残業 = max(日残業の合計, 週残業)
```
（その週の「日ごとの残業の合計」と「週40時間を超えた分」を比べ、**大きい方を採用**）

### BR-22 月をまたぐ週と繰越【確定】
**月末がその週の途中**（週の土曜が翌月にある）場合:

1. その週の表示ラベルは **「（残業繰越）」**、確定残業は**この月では計上しない**（週残業欄には「次月繰越」バッジ）。
2. この週の**当月分**を翌月用の繰越データとして DB に保存（長距離は社員ID×翌月、地場・事務は社員コード×翌月）。内容: 労働・判定用労働・運転・積卸・拘束・深夜・日残業・週残業・**日数（当月側の日数）**。
3. 翌月を表示すると、先頭に **「（前月繰越残業）」行**が出る（`days > 0` のときのみ）。この行の労働時間等は繰越データの値。
4. 翌月の第1週の判定用労働時間には、**繰越の判定用労働時間が加算**される（週40時間判定を前月分と合算するため）。表示される第1週の数値は当月分のみ。
5. 繰越データは、**前月を計算するたびに上書き保存（UPSERT）**される。
   - 計算が走る契機: 前月の画面を開く、集計一覧を読み込む、集計CSVを出力する、保存後の再取得。
   - したがって、**前月の元データを修正した後は、前月を一度開き直さないと翌月の繰越が更新されない**（運用上の注意）。【確定】
6. 月がちょうど土曜で終わる場合は繰越は発生しない。

### BR-23 月間合計【確定】
- 「前月繰越残業」行は**合計に含めない**（当月実績ではないため）。
- 「（残業繰越）」行は、**拘束・労働・運転・積卸・深夜・日残業・週残業の合計には含める**（当月1日〜末日の実績のため）。
- ただし**確定残業の合計には含めない**（翌月に週が確定してから合計される）。
- 月間の休憩合計 = 各週の休憩の合計。

### BR-24 月間サマリの項目【確定】
`get_monthly_summary`

| 項目 | 計算 |
|---|---|
| 出勤日数 | 勤怠種別が「出勤」または「緊急出動」の日数 |
| 欠勤日数 | 「欠勤」の日数 |
| 休日出勤日数 | 法定休出勤 + 所定休出勤 の日数（BR-18） |
| 振替なし法定休出勤 | 日数 / 労働時間（BR-19） |
| 有給消化日数・有給残日数 | BR-25 |
| 労働時間 | 週集計の合計労働時間（補正含む、前月繰越行除く） |
| 早退遅刻時間 | 全日の `hayatai_min` の合計（残業・労働時間の計算には使わない） |
| 確定残業時間 | 週集計の確定残業の合計（BR-23） |

### BR-25 有給サマリ【確定】
- 有給消化日数: 有給管理の `consumed_days` を対象月で合計。
- 有給残日数: 付与（grants）のうち、**期限切れでなく、有効期限が「今日」以降、残日数>0** のものの残日数を合計。**対象月ではなく「現在時点」の残**。
- 有給管理テーブルが無い、または社員コードが空・「―」の場合は「データなし」（画面は「―」表示）。

## 6. 集計一覧・バッジ

### BR-26 集計一覧【確定】
- 対象: 種別管理で長距離に設定された職種の社員（`employee_id` があるもの）＋ 地場・事務に設定された職種の社員。それぞれ月次計算を実行して月間サマリを並べる（社員数分の計算を毎回行うため重い）。
- **お盆/お正月バッジ**: 対象月が **8月**なら 8/13、**1月**なら 1/1 に「出勤」かつデータありの日があれば、「お盆出勤あり」「お正月出勤あり」を氏名の横に表示（目視確認用）。他の月は出ない。

## 7. 警告（アラート）

### BR-27 警告メッセージ一覧【確定】
警告は日次行の先頭（1日目）に持たされ、画面の表の上に表示される。**error**（赤）／**warn**（黄）。

| ID | 種別 | メッセージ（要約） | 発生条件 | 区分 |
|---|---|---|---|---|
| E1 | error | 「{日付} に乗務員コード {a} と {b} の拘束時間データが重複しています。先に履歴期間または元データを確認してください。」 | 同一社員の複数コードの拘束時間ログに同日のデータ（先に読んだ方を採用、後は無視） | 長距離 |
| E1' | error | 「{日付} に乗務員コード {a} と {b} の長距離データが重複しています。」 | 同上（地場・事務の長距離フラグ日） | 地場・事務 |
| E2 | error | 「{日付} の保存済み勤怠編集情報が複数コードに存在します。自動保存せず確認してください。」 | 保存済み編集が同日に複数行存在（社員ID行と旧コード行など） | 長距離 |
| E3 | error | 「この月の前月繰越データが複数の乗組員コードに存在するため、自動適用していません。」 | 繰越データが複数行（衝突）のため繰越を無視 | 長距離 |
| E4 | error | 「{MM/DD}(日)の振替休を割り当てられる日がありません」 | BR-16 で候補日なし | 共通 |
| E5 | error | 「{MM/DD}の振替休を割り当てられる日がありません」 | 所定振替休の自動割当有効時のみ | 共通 |
| W1 | warn | 「所定休が2日を超えています。」 | 所定休（手動含む）が3日以上 | 共通 |
| W2 | warn | 「法定休の合計（法定休{n}日＋法定振替休{m}日＝{t}日）が正常範囲（4〜5日）を外れています。」 | 法定休＋法定振替休が4未満または5超 | 共通 |
| W3 | warn | 「法定休出勤（{a}回）と法定振替休（{b}日）の数が一致していません。」 | 法定休出勤数 ≠ 法定振替休数 | 共通 |
| W4 | warn | 「所定休出勤（{a}回）と所定振替休（{b}日）の数が一致していません。」 | 所定休出勤数 ≠ 所定振替休数 | 共通 |

### BR-28 同日データの重複・コード衝突の扱い【確定】
乗務員コードの複数保有（BR-02）により、同じ日・同じ月のデータが複数コードに存在し得る。**自動で合算も上書きもせず**、次のように扱って警告を出す。

| 対象 | 検出条件 | 表示時の挙動 | 保存時の挙動 | 警告 |
|---|---|---|---|---|
| 拘束時間ログ（長距離／地場の長距離フラグ日） | 同一社員の有効な複数コードに同じ `work_date` | 並び順（日付→コード昇順）で**先の1件だけ採用**、後は無視 | – | E1 / E1' |
| 保存済み勤怠編集（長距離） | 同日に複数行（社員ID行・旧コード行の併存） | 社員IDを持つ行を優先して採用 | **エラーで全体ロールバック**（「保存済み勤怠が複数コードに存在するため、自動更新できません」） | E2 |
| 繰越（長距離） | 同じ社員ID・月に2行以上、または旧コード行（社員ID未設定）が2行以上 | **繰越を適用しない**（繰越なし扱い） | – | E3 |
| 地場・事務の保存／繰越 | 衝突は検出しない（キーが社員コード＋日付／月で一意） | – | – | – |

解消方法は 09 §5.4・§9。

## 8. 保存仕様と表示形式

### BR-29 何が保存されるか【確定】
「保存（更新）」で、**画面に表示されている月の全日分の行**が送信され、日付ごとに UPSERT される。保存項目:

| 項目 | 長距離 | 地場・事務 |
|---|---|---|
| 勤怠種別・振替ラベル | ○（手動行のみ反映される：BR-11） | 同左 |
| 手動フラグ `is_manual` | ○（画面で勤怠種別を変更した行が 1） | 同左 |
| 地場／長距離フラグ | `jiba` | `chokyo` |
| 補正時間 | 常に数値（無効日は10を送信） | 長距離フラグON日のみ数値、OFFは NULL |
| 早退遅刻 | ○（分） | ○（分） |
| 備考 | ○（最大100文字） | ○ |

**保存しないもの**: 始業・終業・拘束・労働・運転・積卸・休憩・深夜・日残業などの時間（毎回再計算）。

- 長距離: DBトランザクション内で全行保存。同日の保存行が複数あると中断して全体ロールバック。
- 地場・事務: 行ごとに `INSERT ... ON DUPLICATE KEY UPDATE`。トランザクションなし（途中でDBエラーなら、それまでの行は保存済み）。
- 「手動」の判定は、画面を開いた状態でユーザーが勤怠種別セレクトを変更したか（`data-auto` 属性）で決まる（ISS-01 も参照）。

### BR-30 時間の表示形式【確定】
`format_min`: 分 → `H:MM`（例 `0`→`0:00`、`59`→`0:59`、`605`→`10:05`、`-90`→`-1:30`、`null`/空→空欄）。
集計CSVのみ「時間の10進数・小数第1位」（例 605分 → `10.1`）。

## 9. 計算例（検証済み）

### 例1: 平日勤務・補正10分（2026年9月、月〜金 労働8:00・補正10分、土日は勤務なし）

| 週 | 期間 | 日数 | 労働時間 | 日残業 | 週残業 | 確定残業 |
|---|---|---|---|---|---|---|
| 第1週計 | 09/01–09/05 | 5 | 32:40（1,960分＝4日×8:10） | 0:40 | 0:00 | 0:40 |
| 第2週計 | 09/06–09/12 | 7 | 40:50（2,450分） | 0:50 | 0:50 | 0:50 |
| 第3週計 | 09/13–09/19 | 7 | 40:50 | 0:50 | 0:50 | 0:50 |
| 第4週計 | 09/20–09/26 | 7 | 40:50 | 0:50 | 0:50 | 0:50 |
| （残業繰越） | 09/27–09/30 | 4 | 24:30（1,470分） | 0:30 | 0:00 | （次月繰越） |
| **合計** | | 30 | **179:40**（10,780分） | **3:40** | **2:30** | **3:10**（=0:40+0:50×3） |

読み方: 1日あたり労働8:00＋補正0:10＝8:10 なので日残業は毎日 0:10。第2〜4週は5日×8:10＝40:50 で週40時間を50分超えるため週残業 0:50。日残業の合計（5日×0:10＝0:50）と等しいので確定残業は 0:50。

翌月（2026年10月）に保存される繰越: 労働 1,470 / 拘束 1,650 / 日残業 30 / 週残業 0 / 日数 4。

### 例2: 翌月（2026年10月）の表示（繰越込み）

| 行 | 期間 | 日数 | 労働時間 | 日残業 | 週残業 | 確定残業 |
|---|---|---|---|---|---|---|
| （前月繰越残業） | 09/27–09/30 | 4 | 24:30 | 0:30 | ― | ― |
| 第1週計 | 10/01–10/03 | 3 | 16:20（2日分のみ表示） | 0:20 | **0:50** | **0:50** |
| 第2〜5週計 | 10/04–10/31 | 7 | 40:50 | 0:50 | 0:50 | 0:50 |
| **合計** | | 31 | 179:40 | 3:40 | 4:10 | **4:10** |

読み方: 第1週は当月分（木・金 2日=16:20）しか表示されないが、**週40時間の判定には前月繰越の24:30が加わる**（24:30＋16:20＝40:50 → 0:50超過）ため、週残業 0:50・確定残業 0:50 となる（日残業の合計 0:20 より大きい方を採用）。

### 例3: 日曜出勤と振替休（2026年9月、火〜土と日曜09/06に出勤、月曜は出勤なし）

- 09/06（日）: 出勤。→ **法定休出勤**バッジ。
- 09/07（月）: 勤怠種別が自動で「**法定振替休**」、ラベル「09/06(日)の振替」。（日曜の次の「勤怠種別が空欄・データなし・日曜でなく・所定休日でなく・手動でない」日）
- 09/13・09/20・09/27（日）: データなし → 「法定休」。
- 法定休（3）＋法定振替休（1）＝4日 → 正常範囲（4〜5日）→ 警告なし。
- 09/14・09/21・09/28（月）: 勤怠種別は空欄「―」のまま。
- 法定休出勤（1回）＝ 法定振替休（1日）→ 件数警告なし。09/06 は「振替済み」で、残業計算に含まれる。

### 例4: 振替休を割り当てられない場合
月〜土を毎日出勤し、さらに日曜（09/06）も出勤して候補日が1日も無いとき → エラー E4「09/06(日)の振替休を割り当てられる日がありません」。09/06 は「振替なし法定休出勤」になり、**その日の労働時間は日残業・週残業から除外**され、月間サマリ・CSVでは別枠（日数/労働時間）で集計される。

### 例5: 所定休日ルール
所属A、土曜（`day_of_week=6`）、対象週 `2,4`。2026年9月の土曜は 09/05（1回目）・09/12（2回目）・09/19（3回目）・09/26（4回目）。→ 所定休日は **09/12 と 09/26**。データのない日は「所定休」。この2日に出勤すると「所定休出勤」バッジ。
