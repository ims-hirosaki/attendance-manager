## 2. 共通仕様

### 2.1 アセット読み込み【確定】
`admin_enqueue_scripts` で、**上記5ページの時だけ** `assets/css/admin.css` と `assets/js/admin.js`（依存: jQuery、フッターで読み込み）を読み込む。バージョン文字列は `AM_VERSION . '.' . filemtime(ファイル)`（キャッシュ対策）。JS には `amData` を渡す（07 参照）。JS はページごとに `amData.currentPage` で分岐する。

### 2.2 社員選択フォーム（SCR-01・02）
- GET フォーム（ページ内再表示）。
- **所属チップ**（`.am-chip`、`data-affil`）: 社員リストに複数の所属がある場合のみ表示。「すべて」＋所属名。クリックで社員セレクトの `option[data-affil]` を表示/非表示に絞り込み、選択中の社員が隠れたら選択解除。
- 「集計表を開く」ボタン（長距離 `#am-btn-open`、地場 `#am-btn-open-jiba`）は**社員が未選択のとき `disabled`**。
- 前月/翌月の矢印リンクは、同じ社員・隣の月の URL（GET）。

### 2.3 日次表の共通挙動【確定】
- 行 `tr[data-date]`、属性 `data-auto`（`true`=自動、`false`=手動）、`data-furikae`（振替ラベル）。
- **勤怠種別セレクト変更**（`.am-kintai-select`）→ その行の `data-auto` を `false`（＝保存時に `is_manual=1`）。
- **行の色**: 日曜=薄い赤背景＋曜日が赤、土曜=薄い青背景＋曜日が青、データなし（日曜・土曜以外）=文字が灰色。日残業>0 のセルは赤太字。
- **バッジ**（日付欄）: 「法定休出勤」（濃い赤茶 `#8b1a1a`）、「所定休出勤」（茶 `#5a3e00`）。
- 勤怠種別の選択肢: `出勤 / 法定休 / 法定振替休 / 所定休 / 所定振替休 / 有給 / 欠勤 / 緊急出動 / ―（空）`（`KINTAI_TYPES` ＋空）。

### 2.4 保存後の再描画（JS 共通）
保存成功後、フラグ（地場/長距離スイッチ）を**操作していなければ**以下を AJAX で再取得して部分更新:
1. `refreshSummary` → 月間サマリの各セル（`[data-ms="…"]`）を更新。
2. `refreshDailyRows` → 警告アラート領域、日次行の勤怠種別・バッジ・時間セルを更新。
3. `refreshWeeklyRows` → 週計テーブルを更新。

フラグを**一度でも操作した場合**は、保存後に `alert('{n}件を保存しました。ページを更新して反映します。')` を出して**ページ全体をリロード**する（データ元が切り替わるため）。

> 実装上の注意: 日次行・週計の更新は **`td:nth-child(n)` の列番号**に依存する（列を追加・並べ替えるとズレる）。

### 2.5 メッセージ表示
- 保存成功: 緑帯「{n}件を保存しました」（4秒後にフェードアウト）。
- 保存失敗: 赤帯「保存に失敗しました：{メッセージ}」／通信失敗「通信エラーが発生しました」。

## 3. SCR-01 長距離

### 3.1 構成
1. ページヘッダー「勤怠管理 | 長距離」、説明文「拘束時間管理データをもとに、長距離ドライバーの月次勤怠データを確認できます。」
2. DBエラー表示（`.am-notice-error`「DBエラー：…」）。社員一覧取得時の `last_error`。
3. **集計条件カード**: 所属チップ／社員名セレクト `#am-select-crew`（`name=am_employee_id`、表示は `[社員コード]氏名`）／対象月 `#am-select-month`（`type=month`, `name=am_month`）／「集計表を開く」`#am-btn-open`。
4. **結果カード**（社員選択済みの場合）:
   - ヘッダー: 前月/翌月リンク、`{YYYY-MM}　{氏名} さんの集計表（長距離）`、**保存（更新）** `#am-btn-save`（`data-employee-id` / `data-month`）。
   - 保存メッセージ領域 `#am-save-message`。
   - **社員情報表** `.am-info-table`: 社員名／社員No.／現行乗務員コード／対象月の使用コード（履歴から解決、読点区切り）／所属。
   - **警告領域** `.am-alerts`（BR-27）。
   - **日次表** `.am-main-table`（15列、下記）。
   - **週計表**（`_weekly-table.php`）。
   - **月間サマリ**（`_monthly-summary.php`、日次が1行以上ある場合）。

### 3.3 保存時に送る値（`#am-btn-save` クリック）
全 `tbody tr[data-date]` から次を収集して `am_chokyo_kintai_save`（API-01）へ POST:
`date`, `kintai_type`, `furikae_label`（`data-furikae`）, `is_manual`（`data-auto==='false'`→1）, `jiba`（トグル）, `hosei_min`（入力が `disabled` なら **10**、そうでなければ入力値（負数→0））, `hayatai_min`（`parseMin`: `H:MM`→分）, `note`。
ボタンは通信中 `保存中...` で無効化。

## 4. SCR-02 地場・事務

SCR-01 との差分:
- 社員セレクト `#am-select-emp`（`name=am_emp`、値=**社員コード**、表示 `[社員コード] 氏名`）、月入力 `#am-select-month-jiba`、ボタン `#am-btn-open-jiba`、保存 `#am-btn-save-jiba`（`data-emp` / `data-month`）、保存メッセージ `#am-save-message-jiba`。
- 社員情報表は3列（社員名／社員No.／所属）。
- 日次表12列目は **「長距離」トグル** `.am-chokyo-input`。
- **長距離トグルを変更**したとき（JS）: 変更フラグ `chokyoToggled=true`。その行の始業・終業セル（3・4列目）が空でなく、かつ「適用開始月より前」でない場合のみ **補正時間を有効化して10に設定**。それ以外は無効化して0。
- 保存データ: `chokyo`（トグル）、`hosei_min`（無効なら10を送るが、サーバー側で `chokyo=0` なら NULL 化）。API は `am_jiba_kintai_save`（API-05）。
- ページ説明: 「打刻ツールのデータをもとに、地場・事務社員の月次勤怠データを確認できます。」
- 日次APIのレスポンスに勤怠種別が無いため、保存後の部分更新では**勤怠種別セレクトは更新されない**。

## 5. SCR-03 集計一覧

### 5.1 構成
1. 対象月カード: 月入力 `#am-sl-month`（既定=今月、`?am_month=`で指定可）、**読み込む** `#am-sl-load`、**CSV出力** `#am-sl-csv`（nonce付きリンク）。
2. 月入力を変更すると、`#am-sl-csv` の `year_month` クエリが JS で書き換わる（読み込みボタンを押さなくてもCSVは変更後の月）。
3. 結果カード: 読み込み中表示 `#am-sl-loading`、エラー `#am-sl-error`、表 `#am-sl-table`（`#am-sl-tbody` に JS が描画）。

### 5.2 一覧の列（11列）
社員コード／社員名（＋バッジ「お盆出勤あり」「お正月出勤あり」）／出勤日数／欠勤日数／休日出勤日数／振替なし法定休出勤（日数 / 労働時間）／有給消化日数／有給残日数／労働時間／早退遅刻時間／確定残業時間。

- 欠勤>0 は赤、休日出勤>0・振替なし>0・早退遅刻>0 はオレンジ、確定残業>0 は赤（それぞれ CSS クラス `am-ms-alert` / `am-ms-warn` / `am-ms-over`）。
- 有給が「データなし」のとき `―`。
- **ページを開いただけでは読み込まれない**（「読み込む」を押して初めて AJAX 実行。社員数が多いと時間がかかるため）。
- データ0件: 「対象月のデータがありません」。
- 通信失敗: 「通信エラーが発生しました」。

## 7. SCR-05 設定

4つのセクションが縦に並ぶ（見出し `.am-settings-section-heading`）。

### 7.1 休日マスタ設定
- 追加・編集フォーム: 所属 `#hm-affiliation`（`emp_get_affiliations()` または有効な `mst_affiliation`）、所定休日（曜日）`#hm-dow`（日〜土、値0〜6）、対象週 `#hm-weeks`（例 `2,4`。注記「第何週かをカンマ区切りで入力（例：第2・第4週なら 2,4）」）、保存 `#hm-btn-save`（編集中は「更新」に変わる）、キャンセル `#hm-btn-cancel`（編集中のみ表示）、メッセージ `#hm-message`。
- 登録済みルール一覧 `#hm-rule-table`（所属／所定休日（曜日）／対象週／状態／操作）。操作: **編集**（フォームへ値を呼び出し）／**無効化・有効化**／**削除**（確認ダイアログ「このルールを削除しますか？」）。変更のたびに一覧を AJAX で再描画（`hmReloadTable`）。状態バッジ「有効/無効」。
- 注意: 編集して保存すると、無効だったルールも**有効に戻る**（API-10）。

### 7.2 種別管理
- 読み込み中表示 `#jt-loading` → 表 `#jt-table`（職種名／長距離／地場・事務／状態）。各職種に**ラジオ2択**（長距離・地場・事務）。**選んだ瞬間に自動保存**（API-14）。成功で状態が「設定済」へ、メッセージ `#jt-message`「「{職種名}」を保存しました」。
- 初期状態は「未設定」（どちらも未選択）。**一度設定した職種を未設定へ戻す操作は無い**。
- 職種が1件も取得できないとき `#jt-empty`:「従業員マスタに職種が登録されていません。先に employee-manager で職種を登録してください。」

### 7.3 補正時間（点呼など）
- 説明: 「長距離の週集計の労働時間に補正時間を加算する開始月を設定します。この月より前の月は補正時間が0扱いとなり、過去の集計は変わりません。」
- 適用開始月 `#hosei-start-month`（`type=month`）＋保存 `#hosei-btn-save`、結果 `#hosei-message`。

### 7.4 未紐付け乗組員コード
- 移行状況カウンタ4つ: 未移行 勤怠編集行／未移行 繰越行／勤怠編集の衝突／繰越の衝突。
- 未紐付けコード表: 乗組員コード／最古日／最新日／データ件数（拘束時間ログにあり、社員マスタにも履歴にも無いコード）。
- 説明: 「…社員情報管理の社員編集画面から「過去コードを追加」してください。」（紐付け操作は本プラグインには無い）

## 9. フロント実装メモ

- jQuery の即時関数で、`amData.currentPage` が一致するページの処理だけ登録。
- ページ間共通のイベント（`.am-chip`、`.am-kintai-select`）は `$(document).on` で常時登録。
- 時間入力のパース `parseMin('H:MM')`: 空→0、`H`のみ→時間、`H:MM`→分換算。**分だけの数字（例 `30`）は30時間として解釈される**。
- アラートの描画は `$('<span>').text(a.message).html()` でエスケープ。
